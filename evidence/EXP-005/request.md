# EXP-005 事前登録 — 利用上限のとき「上限」と表示する (H-07 のうち 429)

Status: **登録済み (変更より前の commit)** / Date: 2026-09-30
仕様: `docs/pdca-spec.md` / バックログ: `docs/hypotheses.md` H-07
きっかけ: ローカル確認 (2026-09-30) で Gemini の無料枠 (1 日 20 回) を使い切り、画面は「エラーが発生しました。」だけだった。本人の一言「上限が来た時の表示をエラーではなく上限の方で」
**この文書の数値・規則は、測った後で変えない。**

## 1. 仮説

- H1: 429 のとき、画面が「上限に達した」ことと「いつ戻るか (または少し待てばよいか)」を表示すれば、本人は失敗をエラーと受け取らず、次に何をすればよいか分かる
- H2: 送れなかった文を入力欄に戻せば、戻った後にそのまま送り直せる

範囲:
- 変えるのは **429 の経路だけ** (サーバの返す文言と種類・画面の表示)
- 混雑 (503) は H-07 の残りとして別カードにする (このカードに含めない)
- プロンプト・成功時の表示・`[perf]` の項目は変えない (EXP-004 の `question_count` に影響させない)

## 2. 表示の規則

| Gemini の上限 | サーバ (status 429) | 画面 |
|---|---|---|
| 1 日の上限 (quotaId に `PerDay`) | `kind: "quota_daily"`・戻る時刻 (太平洋時間 0 時を日本時間で) | 「本日の AI 利用上限に達しました。HH:MM ごろに戻ります」 |
| それ以外の 429 (1 分あたり等) | `kind: "quota_rate"` | 「利用が集中しています。1 分ほど待ってから送り直してください」 |

画面では: 赤いエラーや `alert` ではなく、会話欄の下に「お知らせ」(`role="status"`) として出す。送れなかった自分の発言は会話から外し、文を入力欄に戻す。

## 3. 実験室の判定 (機械的)

| 規則 | 条件 |
|---|---|
| L1 | 1 日の上限の 429 → status 429・`kind` = `quota_daily`・文言に戻る時刻 (HH:MM) が入る |
| L2 | それ以外の 429 → status 429・`kind` = `quota_rate` |
| L3 | 戻る時刻の計算: 固定した現在時刻 (夏時間 1 件・冬時間 1 件) で、日本時間 16:00 / 17:00 になる |
| L4 | 画面の文言を作る関数: 429 + `kind` から上の表の文になる。429 以外は null (今までどおり) |
| L5 | `[perf]` の行は status 429 のまま・項目は増えない。`npm test` 全件成功・`tsc` 0・`next build` 成功 |

## 4. 本人の判定

| 判定 | 条件 |
|---|---|
| **定着** | 次に上限に達したとき、本人が「エラーと思った / 何をすればよいか分からない」を挙げない |
| **巻き戻し** | 表示が出ない・送り直せない・前より分かりにくいと本人が報告した (Human Gate。Claude は提案まで) |
| **判定不能** | 14 日以内に上限に達しない |

上限にわざと達するための利用はしない (枠を無駄にするため)。自然に達したときだけ判定する。
