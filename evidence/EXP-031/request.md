仕様: `docs/product-spec.md` §0 (KGI は作る時に固定・KPI は仮置き・Plan で KDI・ToDo は毎日決め直す)
きっかけ: 本人「KDI を達成するために ToDo を毎日設定して実行して、Plan を AI と一緒に考えて ToDo を 3 つタスク化する。KDI を 3 つぐらい作成する。ToDo も 3 つぐらい作成する。1 日 9 つ程タスクをやる。壁打ちしながら ToDo を Plan に入れて一緒に何をするか壁打ちする。判定基準もつくり、何をもって達成かを考えて実行してチェックして壁打ちしながら見直して、調整で仮説を立てながら次に何をするのかなど今までのデータや進捗状況や期限を考えながら考える」
**この文書の数値・規則は、測った後で変えない。**

## 1. 仮説と範囲

- H1: AI が KDI を 3 つほど一緒に決め、毎日 KDI ごとに今日の ToDo を 3 つほど (判定基準つき) 一緒に決めれば、本人は 1 日 9 つほどのタスクを迷わずに実行・チェックできる
- 範囲: 次に決める段の規則 (KDI 3 つ・今日の ToDo を KDI ごとに 3 つ)・ToDo の期日は今日・判定基準 (項目の target 欄) を AI が一緒に決める・「今日」タブを KDI ごとにまとめて判定基準を出す・目安を 9 つに
- 範囲外: KPI を AI が書き換える (次のカード)・週末の判定と調整 (次のカード)・ToDo の繰り返し

## 2. 決まり

`lib/hierarchy-step.ts`:
- 目安: `KDI_TARGET = 3` (プロジェクトの KDI の数・棚上げは数えない)・`TODO_PER_KDI = 3` (KDI ごとの今日の ToDo)
- `nextHierarchyStep(items, today)`:
  1. KGI が無い → kgi / KPI が無い → kpi (KGI の下)
  2. 棚上げでない KDI が 3 つ未満 → kdi (親 = KDI の一番少ない KPI・同じなら古い順)
  3. 棚上げでない KDI (古い順・3 つまで) のうち、期日が今日の ToDo が 3 つ未満の最初の KDI → todo (親 = その KDI・`have` = 今日の数)
  4. 全部そろっている → null
- `parseProposedItems`: todo の段は期日が空なら今日にする・**期日が今日でない ToDo は捨てる**・数は `TODO_PER_KDI - have` まで (kpi・kdi は 3 つまで)
- `hierarchyText`: target は「判定基準」と書く

`/api/coach` のプロンプト (段ごとの決め方だけを変える):
- KDI: 「KPI を達成するための行動の量・頻度。全部で 3 つほど。判定基準 (何をもって達成か) を一緒に決めて target に入れる」
- 今日の ToDo: 「KDI を達成するための今日の具体的な作業。この KDI に今日 3 つほど (1 日 9 つほど)。前の日の記録 (〇△×・明日はこうする)・進み具合・期限を見て決める。判定基準を target に入れる。期日は今日」
- 出力の items の target を「判定基準」と説明する

画面:
- 「今日」タブの今日の ToDo を KDI ごとにまとめ、各 ToDo に「判定基準: …」を出す。目安の文「KDI ごとに 3 つ・1 日 9 つほど」
- 目安を超えたときの案内は 9 つを超えたとき (今の「3 つに絞ると」を置き換える)
- 会話に送るボタンの文を「今日の ToDo を KDI ごとに 3 つずつ決めたい」に
- 階層の追加欄の「目標値」を「目標値・判定基準」に
