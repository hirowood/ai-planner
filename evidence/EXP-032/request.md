## 1. 仮説と範囲

- H1: AI が ToDo の判定基準・最近 7 日の進み具合・KPI と KGI の期限までの日数を見て、できた所から判定を一緒に決め、調整の型 (KPI / 行動 / そのまま続ける) と次の仮説を 1 つ立てれば、本人は落ち込まずに次に何をするかを決められる
- 範囲: 進み具合の要約 (純粋な関数)・AI への記録に進み具合と期限を足す・判定と調整の決め方の文・AI が返す仮説をノート (種類「仮説」) に残す・画面に仮説を残したことを知らせる
- 範囲外: AI が KPI を書き換える (次のカード)・週末の画面 (まとめの表示)・グラフ

## 2. 決まり

`lib/progress.ts` (純粋):
- `progressText(items, today)`:
  - KGI の行: 題・期日・「あと N 日」(期日が無ければ「期日なし」・過ぎていれば「N 日過ぎ」)
  - KPI ごと: 題・判定基準 (target)・期日とあと N 日
  - KDI ごと (棚上げは除く): 最近 7 日 (今日を含む) の ToDo の数と状態の内訳 (実行・成功・失敗・棚上げ・調整・未実行)・「できた割合」= (実行 + 成功) / 未実行以外の数 (0 件なら「まだ無し」)
  - 本人の書いた文は neutralize・題は 60 字で切る・無ければ「(まだ無し)」
- `daysBetween(a, b)`: 日付 2 つの差 (日)

`/api/coach`:
- `<Records>` に「#### 進み具合と期限 (最近 7 日)」として `progressText` を入れる
- 判定と調整の節 (新しい文):
  - 判定は ToDo の判定基準で決める。**できた所から先に**伝え、できなかったことは責めずに理由を一緒に探す。自分に厳しくしすぎないよう声をかける
  - 調整は「KPI / 行動 / そのまま続ける」の型から選んでもらう (EXP-022 の「課題 / 行動 / そのまま続ける」を本人の訂正に合わせて置き換え)。期限までに KGI に届かなそうなら KPI の見直しを相談する
  - 次の仮説を 1 つ「〜すれば、〜になるはず」の形で一緒に立てる。本人が同意した仮説だけ JSON の `"hypothesis"` に入れる (無ければ "")
- サーバは `hypothesis` を検査し (文字列・前後の空白を除いて 1〜300 字・1 つ)、ノート (種類「仮説」) として保存する。返事に `hypothesisSaved: true/false`・`[perf]` に `hypothesis_saved` (真偽)

画面: `hypothesisSaved` が true なら「仮説をノートに残しました」と知らせ、ノートを読み直す
