# EXP-034 事前登録 — ToDo を「実行中」にし、「完了」を押すと AI が判定の質問から C → A → 次の Plan へ一緒に進める

Status: **登録済み (変更より前の commit)** / Date: 2026-10-02
仕様: `docs/product-spec.md` §0 (Do → Check → Action を AI と一緒に・一人で落ち込まない)
きっかけ: 本人「ToDo を実行中にする。完了を押したら判定して AI からの質問が出て適切に答える。C と A を AI と話しながら、どうだったかを振り返って、調整することを考えて、次の Plan に対して考える」
**この文書の数値・規則は、測った後で変えない。**

## 1. 仮説と範囲

- H1: ToDo を「始める → 完了」の 2 つのボタンで進め、完了と同時に AI が判定基準に沿った質問を 1 つ出し、本人の答えで判定 (成功 / 失敗 / 調整) を決め、そのまま振り返り → 調整 → 次の Plan まで話せば、本人は ToDo ごとに C と A を回せる
- 範囲: 状態「実行中」を足す・「今日」タブの ToDo に「▶ 始める」「✓ 完了」・完了で会話に送る・AI に「判定を待っている ToDo」を渡す・AI が返す判定をサーバがその ToDo に入れる
- 範囲外: 実行時間の記録 (始めた時刻)・タイマー・通知

## 2. 決まり

状態 (`lib/plan-items.ts`):
- `doing` = 「実行中」を足す (STATUS_ORDER: 未実行 → 実行中 → 実行 → 棚上げ → 失敗 → 成功 → 調整)
- 「実行」(done) は「完了した・まだ判定していない」として扱う

画面 (「☀️ 今日」タブの今日の ToDo):
- 未実行 → 「▶ 始める」(押すと実行中)
- 実行中 → 「✓ 完了」(押すと実行にし、会話へ「『題』を完了しました。判定をお願いします」を送る)
- 実行 (判定待ち) → 「判定待ち」の印と「AI と判定する」(同じ文を送り直す)
- 成功 / 失敗 / 調整 → 状態の印だけ
- 今の状態の選択も残す (手で直せる)

`lib/judgement.ts` (純粋):
- `pendingJudgement(items, today)`: 判定を待っている ToDo = 状態が「実行」の ToDo のうち、期日が今日から 7 日前までで一番新しく更新されたもの (無ければ null)
- `parseJudgement(x)`: "succeeded" / "failed" / "adjusted" のどれかなら返す・それ以外は null
- `completeMessage(title)`: 「『題』を完了しました。判定をお願いします」

`/api/coach`:
- 判定を待っている ToDo があれば「### 判定を待っている ToDo」の節を入れる (題・判定基準・期日・本人の書いた文は neutralize)
  - まず判定基準に沿って「できたか」を聞く質問を 1 つ・答えの候補 ("choices") に「判定基準を満たした」「一部できた」「できなかった」を入れる
  - 本人が答えて判定が決まったら `"judgement"` に succeeded (満たした) / failed (できなかった) / adjusted (一部できた・やり方を変える) を入れる (決まっていなければ "")
  - 判定のあとは、できた所から振り返り (C) → 調整の型 (A・KPI / 行動 / そのまま続ける) → 次の Plan (次の ToDo・仮説) の順に 1 つずつ聞く
  - 判定を待っている間は、階層に項目を足さない (`items` は使わない)
- サーバは `judgement` を検査し、判定を待っている ToDo (持ち主の・その時点で状態が「実行」のもの) だけを更新する。返事に `judged: { title, status }`・`[perf]` に `judgement_applied` (真偽)

画面: `judged` があれば「『題』を成功と判定しました」などと知らせ、階層を読み直す
