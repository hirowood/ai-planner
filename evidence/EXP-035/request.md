## 1. 仮説と範囲

- H1: 候補をボタンで選んだ時点でサーバが階層に足し (AI の確認を待たない)、KDI が 1 つできたらすぐ今日の ToDo に進み、候補を過去の記録から根拠つきで提案すれば、「はい、登録する」の繰り返しが無くなり、少ない往復で ToDo に着く
- 範囲: 段の順 (KDI 1 つで ToDo へ)・AI が返す候補 (`candidates`)・候補のボタンを押したら足す (`pick`)・確認しない約束と過去の記録からの提案の文
- 範囲外: 判定の流れ (EXP-034 のまま)・KPI の書き換え

## 2. 決まり

段の順 (`nextHierarchyStep`・EXP-031 の順を置き換える):
1. KGI が無い → kgi / KPI が無い → kpi
2. 棚上げでない KDI が **0** → kdi
3. KDI (古い順・3 つまで) のうち今日の ToDo が 3 つ未満の最初の KDI → todo
4. KDI が 3 つ未満 → kdi (KDI の少ない KPI の下)
5. 全部そろっている → null

候補 (`lib/hierarchy-step.ts` の `parseCandidates(x, step, projectId)`):
- AI の `"candidates": [{ "title", "target" }]` を、今の段として `parseProposedItems` と同じ検査 (数の上限・今日の期日) で通したものの題と判定基準だけ (3 つまで)・kgi / null の段や判定待ちの間は []
- 返事に `candidates: [{ title, target }]`

選んだら足す (`/api/coach` の `pick`):
- 本文に `pick: { title, target? }` があり、判定待ちでなければ、AI に聞く前にサーバが今の段として `parseProposedItems([pick])` で検査して `createItem` で足す (親と段はサーバ)
- 足した後の項目で段を決め直し、プロンプトに「### いまユーザーが選んで足した項目: 段『題』。確認の質問はせず、次へ進んでください」を入れる
- `itemsAdded` に含める・`[perf]` の `items_added` に数える・`pick_added` (真偽) を足す

プロンプト:
- 段の決め方に「候補は "candidates" に 2〜3 個入れる。ユーザーがボタンで選ぶとサーバがそのまま足す。**選ばれた後や、ユーザーが自分の言葉で決めた後に『よろしいですか』と確認しない**」
- 「候補は記録 (できた ToDo・失敗した ToDo・仮説・毎日の記録・ノート) から作り、『前に〜できたので、〜をやってみませんか』のように根拠を添えて自分から提案する」
- `items` の説明を「ユーザーが自分の言葉で決めたとき (確認は取らない)」に

画面: 返事の `candidates` を答えの候補のボタンとして出す (題・ほかの choices より前)。候補のボタンを押すと、その題を送り、`pick` を付ける
