# EXP-012 事前登録 — 種類を自由に入力できるようにする

Status: **登録済み (変更より前の commit)** / Date: 2026-09-30
仕様: `docs/product-spec.md` / 前のカード: EXP-008 (種類は決まった 3 つだけ・L1 で「知らない種類は null」)
きっかけ: EXP-008 のローカル確認中の本人の一言「種類は入力もできるようにしてください」
**この文書の数値・規則は、測った後で変えない。** EXP-008 の L1 (知らない種類は null) は EXP-008 の判定のまま残し、このカードで置き換える。

## 1. 仮説と狙う指標

- 動かしたい指標: KGI (本人の点数)。目的に合った名前で分けられれば、記録を続けやすい
- H1: プロジェクトの種類 (習慣・学習・仕事) とノートの種類 (事実・データ・考え) に「その他」を足し、文字で入れられれば、本人が自分の分け方で記録できる
- 範囲: 検査 (`lib/projects.ts`)・表の制約・2 つの画面の種類の欄。既定の 6 つは今までどおり選べる (保存する値も今までどおり `habit` など)

## 2. 決まり

- 種類の値 = 既定の値 (`habit`・`learning`・`work` / `fact`・`data`・`thought`) か、自由入力の文字 (trim して 1〜20 字・制御文字を含まない)
- 表示: 既定の値は日本語の名前 (習慣 など)、自由入力はそのまま
- 画面: ラジオに「その他」を足す。選ぶと「種類の名前」の入力欄が出る (ラベルつき)。空のまま作ろうとしたら欄の下にお知らせ
- 表: `projects.category` と `notes.kind` の check 制約 (3 つのどれか) を外す (`alter table ... drop constraint if exists`)。字数は API の検査で守る
- 自由入力の種類はログに出さない (`[perf]` は今までどおり数だけ)

## 3. 実験室の判定 (機械的)

| 規則 | 条件 |
|---|---|
| L1 | 既定の 6 つはそのまま通る。自由入力「健康」「読書メモ」が通る・前後の空白を外す・21 字・空・改行やタブなどの制御文字・文字列でない値は null |
| L2 | 表示の名前: 既定は 習慣 / 事実 など、自由入力はそのまま |
| L3 | 画面: 両方の種類の欄に「その他」のラジオと、ラベルつきの「種類の名前」の入力欄がある (既定では入力欄は選んだときだけ出る) |
| L4 | `npm test` 全件成功・`tsc` 0・lint 0 errors・`next build` 成功。持ち主の絞り込みのテスト (EXP-008 L2) が通る |
| L5 | 本物の Neon で移行を流し直して、自由入力の種類でプロジェクトとノートを作れる (本人のローカル確認) |

## 4. 本人の判定

| 判定 | 条件 |
|---|---|
| **定着** | 本人が自由入力の種類でプロジェクトかノートを 1 つ以上作り、一番の困りごとに「種類」を挙げない |
| **巻き戻し** | 入力できない・保存されない・表示が崩れる、と本人が報告した (Human Gate) |
| **判定不能** | 14 日以内に自由入力の種類を使わない |
