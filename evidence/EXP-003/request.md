# EXP-003 事前登録 — AI の返答の Markdown を整形して表示する

Status: **登録済み (変更より前の commit)** / Date: 2026-09-30
きっかけ: 本番の回 1 で本人の一言「返答の Markdown が変換されず (`**`・`###` がそのまま) 読みにくい」(`evidence/EXP-002/field.md`)
計画上の位置: `docs/ux-pdca-plan.md` の順 (A 質問 → B レイアウト → C 見た目) とは別に、**表示の欠陥の修正**として先に入れる (本人の決定)

**この文書の数値・規則は、測った後で変えない。**

## 1. 仮説

- H1: AI の返答を Markdown として整形して表示すれば (太字・見出し・箇条書き・表)、本人が読みにくさを一番の困りごととして挙げなくなる
- H2 (悪化しないこと): 予定案の取り出しと登録、ストリーミング中の表示は変わらない
- H3 (安全): 返答に HTML が入っていても、HTML として実行・表示しない (文字として扱う)

範囲:
- 変えるのは**画面の表示だけ** (AI の返答の吹き出し)。本人のメッセージは、これまでどおり文字のまま表示する。
- プロンプト・サーバ・ストリーミングは変えない。したがって EXP-002 の比 (`first_chunk_ms / total_ms`) は混ざらない。

## 2. やり方

- 部品: `react-markdown` 10.1.0 + `remark-gfm` 4.0.1 (表・取り消し線・チェックリスト)。どちらも MIT。新しい依存なので、出所・版・リスク・検証を `dependency-markdown.md` に書く。
- 生の HTML は表示しない (`react-markdown` の既定。`rehype-raw` 等は入れない)。
- 表示は小さな部品 (`MessageContent`) に分け、`page.tsx` からは AI の返答にだけ使う。

## 3. 実験室の判定 (機械的)

| 規則 | 条件 | 満たさなければ |
|---|---|---|
| L1 (H1) | 代表的な返答 (見出し・太字・箇条書き・表・コードブロック) を `MessageContent` で描画した HTML に、`**`・`###`・`- ` の生の記号が残らず、`<strong>`・`<h3>`・`<ul>`・`<table>` がある | 不採用 |
| L2 (H3) | `<script>`・`<img onerror>`・`<a href="javascript:">` を含む返答を描画しても、その要素・属性が HTML として出ない | 不採用 (安全の欠陥) |
| L3 (H2) | `npm test` 全件成功 (既存の振る舞い・計測のテストを含む)・`next build` 成功 | 不採用 |
| L4 | Preview のログイン前の画面で A11Y_AUTOMATED が違反 0 (EXP-002 と同じ手順) | 不採用 |

L1〜L4 がすべて満たされたときだけ、本人のローカル確認に進む。

## 4. 本人の判定 (現場)

点数の基準 (2026-09-30 に本人へ提示した基準・この回から使う):

| 点 | 基準 |
|---|---|
| 5 | 計画を実際にそのまま使う。読みやすく、手間もかからなかった |
| 4 | 計画は使うが、不満が 1 つ (読みにくい・質問が多い など) |
| 3 | 計画はできたが、自分で直さないと使えない |
| 2 | 計画まで行ったが役に立たない、または読みにくくて疲れた |
| 1 | 途中でやめた、または壊れた |

一言は「一番困ったこと」を 1 つ。

判定 (本番に反映後、最初の本人の利用 1 回で決める):
- **定着**: 一番困ったことに「読みにくさ (記号がそのまま・崩れて読めない)」が挙がらない、かつ表示の崩れ・エラーの報告が無い
- **巻き戻し**: 表示が崩れて読めない、または予定案の登録ができない、と本人が報告した (Human Gate。Claude は提案まで)
- **判定不能**: 本人が 14 日以内に使わない

点数そのものは判定に使わない。この回から基準が決まったので、以降のサイクルの基準値として記録する (質問の中身・見た目など、読みやすさ以外の要因も点数に入るため)。
