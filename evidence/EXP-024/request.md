# EXP-024 事前登録 — KGI は決まったら動かさない (変わるのは KPI・KDI・ToDo)

Status: **登録済み (変更より前の commit)** / Date: 2026-09-30
きっかけ: 本人「KGI が決まったらそれに対する KGI は動かさない。KPI と KDI と ToDo が変わるもの」
**この文書の数値・規則は、測った後で変えない。**

## 1. 仮説と範囲

- H1: KGI (期日と数値のゴール) を固定し、変えられるのを KPI・KDI・ToDo だけにすれば、長期の目標がぶれず、調整は手段 (KPI・KDI・ToDo) の側で行われる
- 範囲: 階層の KGI の固定 (サーバと画面)・AI が Plan の「目標 (KGI)」を上書きしない
- KGI を変えたいとき: 新しいプロジェクト (新しいゴール) として作る (このカードでは作り直しの画面は作らない)

## 2. 決まり

- 階層 (`plan_items`) の KGI: 作った後は `title`・`target`・`dueDate` を変えられない (`PATCH` に含まれていれば 409 `{ error: "KGI は決まったら変えません" }`)。`status` だけは変えられる (最後に成功 / 失敗を付けるため)。KGI は消せない (`DELETE` は 409)
- KPI・KDI・ToDo: 今までどおり変えられる・消せる
- AI (`/api/coach`): 今の Plan の `kgi` が埋まっていれば、AI の返した `kgi` を採らない (空のときだけ採る)。プロンプトにも「KGI が決まっていれば KGI を変える提案はしない。変えるのは KPI・KDI・ToDo」を足す
- 画面: 階層の KGI の行は 🔒 と「KGI は固定」を出し、期日の入力と「消す」を出さない (状態の選択は出す)。Plan の要点の「目標 (KGI)」は、階層に KGI があればそのタイトルを読み取り専用で出す

## 3. 実験室の判定

| 規則 | 条件 |
|---|---|
| L1 | repo / API: KGI の title・target・dueDate の更新は 409・status だけの更新は 200・KGI の削除は 409・KPI の更新と削除は今までどおり |
| L2 | `/api/coach`: 今の Plan に kgi があるとき、AI が別の kgi を返しても保存される Plan の kgi は元のまま・空のときは採る。プロンプトに固定の一文 |
| L3 | 画面: KGI の行に 🔒 と「KGI は固定」・期日の入力と消すボタンが無い・状態の選択はある。KPI の行には期日と消すがある |
| L4 | `npm test` 全件成功・`tsc` 0・`next build` 成功 |
