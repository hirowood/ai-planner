# ai-planner 継続改善 (PDCA) の仕様

Date: 2026-09-30 / 置き換え: `docs/ux-pdca-plan.md` の「進め方」を、毎回回せる手順として固定したもの
目的: **小さな変更 1 つ → 少ないデータで確かめる → 次の仮説**を、止まらずに繰り返す

## 1. 役割

| 誰 | すること |
|---|---|
| 本人 | 普段どおり使う / 使った後に **点数と一番困ったこと** を伝える / 本番へのマージと巻き戻しを決める |
| Claude | ログの回収・集計 / 意見を仮説にしてバックログへ / 1 枚ずつカードを作る (事前登録 → 変更 → 検査) / 判定の提案 |

## 2. 1 回の利用ごとにすること (毎回・5 分以内)

1. 本人が使う (本番、またはローカルでの確認)
2. **1 時間以内に** 本人が伝える (ログは約 1 時間で消えるため):
   - 点数 (下の基準)
   - 一番困ったこと (1 つ・一言)
3. Claude がすること:
   - `[perf]` 行を回収し、`evidence/FIELD-LOG.md` に 1 行で記録する
   - 一番困ったことが新しいものなら、`docs/hypotheses.md` に観察として足す

点数の基準:

| 点 | 基準 |
|---|---|
| 5 | 計画を実際にそのまま使う。読みやすく、手間もかからなかった |
| 4 | 計画は使うが、不満が 1 つ |
| 3 | 計画はできたが、自分で直さないと使えない |
| 2 | 計画まで行ったが役に立たない、または疲れた |
| 1 | 途中でやめた、または壊れた |

## 3. 1 サイクル (1 枚のカード) の流れ

```text
バックログから 1 つ選ぶ → Plan (request.md を事前登録) → Do (変更は 1 つ)
→ Check (実験室 → ローカルで本人が見る → PR → 本人がマージ → 本番の利用 1〜3 回)
→ Act (result.md に 定着 / 巻き戻し / 判定不能・次の仮説をバックログへ)
```

選び方: **効果の大きさ (本人の困りごとに直結か) ÷ 手間** が大きいものから。迷ったら本人に 1 問だけ聞く。

## 4. 小さなデータで決めるための規則

- **測る前に決める**: 何が見えたら「良くなった」か (指標・閾値・件数) を `request.md` に書いてから変える。測った後に変えない。変えるなら新しいカード番号で登録し直す。
- **1 回に 1 つだけ変える**: 同じ指標に効く変更を 2 つ同時に出さない (どちらが効いたか分からなくなる)。
- **件数は小さくてよい。ただし数値を書く**: 例「次の 2 回の利用で、一番困ったことに X が挙がらない」。足りなければ「判定不能」にして PASS にしない。
- **機械の指標 + 本人の声**: ログの数値 (時間・往復数・質問の数) と、本人の点数・一言の両方で見る。食い違ったら本人の声を優先し、指標の方を疑う (EXP-002 で、比の指標が体感とずれうると分かった)。
- **ログに出すのは数・真偽・時間だけ**: 会話の本文・予定の中身は出さない。

## 5. リズム

| 間隔 | すること |
|---|---|
| 利用のたび | 回収・記録・観察をバックログへ (§2) |
| 利用 1〜3 回ごと | 進行中のカードを判定する (§3 の Act) |
| カードを閉じるたび | バックログの並べ替え → 次のカードを 1 つ選ぶ |

同時に進めるカードは原則 1 枚。表示の欠陥など、指標が混ざらないものだけは並行してよい (例: EXP-003 は表示だけで、サーバの時間を変えない)。

## 6. 置き場所

| もの | 場所 |
|---|---|
| 仮説のバックログ | `docs/hypotheses.md` |
| 利用ごとの記録 | `evidence/FIELD-LOG.md` |
| カード | `evidence/EXP-xxx/` (`request.md` → `result.md`) |
| 計測の定義 | `lib/perf.ts` (出してよい項目の型) |
| カードの作り方 (並列・PERT・振り返り) | `docs/parallel-cycle-spec.md` / 雛形 `docs/plans/cycle-template.json` / 教訓 `docs/cycle-lessons.md` |
