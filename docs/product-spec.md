Date: 2026-09-30 (v1 を置き換え) / 調査: `docs/research/onisoku-pdca.md`
出典 (本人・2026-09-30):
- 「計画アプリというより PDCA での改善継続アプリで、データなど取っていくアプリにしたい。AI を補助に PDCA を立てやすくすることが目的」
- 「現状 P と C と A に課題があり、計画や判断基準が漠然としている。改善も漠然としているため継続できない。計画的に長期的な視野を持った PDCA を回したい」
- 「チャットが 2 つあるので 1 つにまとめて」「鬼速PDCA で回し、1 日課題 3 つを決めて改善して取り組み、判断して調整して進み続ける」
- 「今までの記録や結果やデータを参考に、チャットの会話やアドバイスに反映して」

## 0. 差別化 — 一人で抱えない PDCA (本人・2026-10-01)

> このアプリの差別化はコーチやメンターがいることで挫折しない・相談ができる・適切な行動を一緒に考えられる・次にやる行動や判定など自分に厳しくならない。データを取ることで今までの成長や今までのデータを使うことができる。Plan を一緒に考えてもらい、何をするかも一緒に壁打ちして、判定も一人で落ち込まずに決めて、調整も一緒に壁打ちしながらできる。落ち込んでも相談しながらちょっとずつ成長や仮説を立てながら進むアプリ。

目標の決め方 (本人・2026-10-02 の訂正):

> 何をするのか目標と目的など KGI をまずプロジェクトの最初に決める。KGI を壁打ちしながら決める。KGI は変えないようにして、これを目標に行動するようにする。KGI を達成するために KPI をまず仮置きする。KPI を壁打ちしながら決める。目標が達成できないようであれば壁打ちしながら KPI を変更したりする。Plan では KDI と ToDo を壁打ちしながら決める。KGI はプロジェクトを作る時に SMART で最初に決める。

| いつ | 何を | 動かすか |
|---|---|---|
| プロジェクトを作る時 (最初に 1 回) | KGI (目的・目標) を SMART で壁打ちしながら決める | **変えない** (これを目標に行動する) |
| KGI が決まったら | KGI を達成するための KPI を壁打ちしながら **仮置き** する | 期限までに KGI に届かなそうなら、壁打ちしながら **変える** |
| 毎回の Plan | KPI を達成するための KDI と ToDo を壁打ちしながら決める | 周ごとに決め直す |

| PDCA の段 | 一緒にすること (AI はコーチ・メンター) | 記録 (データ) |
|---|---|---|
| Plan | KDI と ToDo を壁打ちで一緒に決める (KGI は作る時に固定・KPI は仮置きを必要なら直す) | 階層 (plan_items) |
| Do | ToDo を予定に入れ、次にやる行動を一緒に決める | 予定・ToDo の状態 |
| Check | 判定を一人で落ち込まずに決める。自分に厳しくしすぎない (できた所から見る) | 1 日の記録 (〇△×・良かったこと) |
| Action | 調整 (課題 / 行動 / そのまま続ける) と次の仮説を一緒に立てる | 週末の Check・Action |
| 全体 | 落ち込んだときに相談できる・挫折しない | 今までの成長を記録から示す |

判断の物差し: 新しいカードは「一人で抱えずに済むか」「記録が次の相談に使われるか」のどちらかに効くこと。

## 1. 形

```text
プロジェクト (習慣 / 学習 / 仕事 / 自由入力)
 └ KGI: 作る時に SMART で壁打ちして決める・変えない   ← AI が漠然とした言葉を数と期日に直す
    └ KPI: KGI を達成するために仮置きする・届かなそうなら壁打ちして変える
       └ Plan (毎回): KDI (行動の量・頻度) と ToDo を壁打ちで決める → ToDo を予定に入れる
          毎日:   今日の ToDo をやる → 記録 (〇△×・良かったこと 3 つ・明日はこうする)
          週末:   KDI・KPI の進み具合を見て判定 (一人で落ち込まずに・できた所から)
          調整:   型から 1 つ (KPI / 行動 / そのまま続ける)・KGI は変えない → 次の周へ
 長期の見通し: KPI・KDI の達成率の推移 (今までの成長)
```

## 2. 全体に通す決まり

- **チャットは 1 つ**: プロジェクトを選ぶと、そのプロジェクトの会話 1 本だけ。AI は今の段 (Plan / 今日の 3 つ / 記録 / 判定 / 調整) を知っていて、次にすることへ 1 つずつ誘導する
- **記録を見て話す**: AI には毎回、プロジェクトの記録 (KGI・Plan・ノート・過去の周の結果・直近の会話) を渡す。アドバイスには根拠の記録を添える。記録に無い数字は作らない
- **漠然を数に**: 判定基準・KPI・KDI は必ず数と期日を持つ。数が無い案には、AI が数の入った言い直しを 2〜3 個示す
- 入力欄に直接書くか、会話から反映するかを選べる
- データはデータベース (Neon)・持ち主で絞る。ログは数と時間だけ
