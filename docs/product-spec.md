# ai-planner の製品の形 — 目的別プロジェクトで PDCA を回すコーチ

Date: 2026-09-30 / 出典: 本人の要望 (2026-09-30)
- 「目標と目的を入力欄に入力、わからなければ壁打ちでチャットする。入力するか会話を反映するかで Plan を一緒に決める」
- 「Check で Plan で決めた判定基準と成果物で出来たかを一緒にレビューして判定」「A で調整や改善案を考え、次の Plan の仮説を立てる」
- 「ノートも作成する。事実などデータなど記録をとる。データベースも必要」
- 「プロジェクトをいくつか作れるようにする。習慣や学習や仕事など目的によって作れるようにする」
- 決定: 保存先 = データベース (Vercel の Postgres = Neon)・作る順 = 土台 → Plan → Check → Act (1 段ずつ)

## 1. 形

```text
プロジェクト (習慣 / 学習 / 仕事 ・ 目的)            ← 複数作れる
 ├─ サイクル (PDCA 1 周)                              ← プロジェクトの中で何周も回す
 │   ├─ Plan : 目的・目標 (KGI)・KPI・行動 (KDI)・判定基準・成果物・仮説
 │   ├─ Do   : 行動をカレンダーに登録して本人が行う
 │   ├─ Check: 判定基準と成果物で「できたか」を一緒にレビュー → 判定
 │   └─ Act  : 調整・改善案 → 次の Plan の仮説
 └─ ノート (事実 / データ / 考え)                     ← いつでも記録。サイクルに結びつけられる
```

どの段も **「入力欄に書く」か「チャットで壁打ちして、会話を反映する」** のどちらかで埋める。

## 2. データ (Postgres)

| 表 | 主な列 | 備考 |
|---|---|---|
| `projects` | id・owner (Google のメール)・name・category (`habit` / `learning` / `work`)・purpose・created_at・archived_at | |
| `notes` | id・owner・project_id・kind (`fact` / `data` / `thought`)・body・cycle_id (任意)・created_at | 事実・データ・考え |
| `cycles` | id・owner・project_id・phase (`plan` / `do` / `check` / `act` / `done`)・plan (jsonb)・check (jsonb)・act (jsonb)・created_at・updated_at | EXP-009 以降 |

- すべての読み書きはサーバで `owner = ログイン中のメール` に絞る (他人のデータは見えない・書けない)
- 接続の秘密 (`DATABASE_URL`) はサーバだけが読む。画面やログに出さない
- ログ (`[perf]`) には件数・種類・時間だけを出し、名前・目的・本文は出さない

## 3. 作る順 (1 カード = 1 段)

| カード | 中身 | 状態 |
|---|---|---|
| EXP-007 | Plan の入力欄 (カレンダーに保存する版) | **取り下げ** (保存先がデータベースに変わったため・測る前) |
| EXP-008 | 土台: データベース・プロジェクト (作る・選ぶ・種類と目的)・ノート (事実 / データ / 考えを書く・一覧・消す) | 次 |
| EXP-009 | Plan: プロジェクトの中で、入力欄と「会話から反映」で Plan を決めてデータベースへ保存・行動をカレンダーへ | |
| EXP-010 | Check: Plan の判定基準と成果物を見ながら、入力か壁打ちで判定する | |
| EXP-011 | Act: 改善案と次の仮説 → 次のサイクルの Plan へ引き継ぐ | |
| (後) | チャットのプロンプトを段に合わせる・プロジェクトの種類ごとの聞き方 | |
