# ai-planner UX 改善の PDCA 計画

Date: 2026-09-30 / 前提: PR #1 (計測 + ストリーミング) を本番へマージ済み (`21fc799`)
対象: **A 質問の中身 → B レイアウト → C 見た目** の順に、1 サイクル 1 テーマで回す (本人の決定)

## 1. 1 サイクルの形 (共通)

`evidence/EXP-xxx/` の実験カード 1 枚を、1 サイクルの単位にする (EXP-001・002 と同じ仕組み)。

| 段 | やること | 担当 |
|---|---|---|
| **Plan** | 仮説・指標・閾値・判定規則を `request.md` に書き、**変更より前の commit** にする | Claude (本人が確認) |
| **Do** | 小さな変更を 1 つだけ入れる (同じ指標に効く変更を 2 つ同時に入れない) | Claude |
| **Check** | 実験室 (テスト・ベンチ・画面検査) → Preview → 本人の実利用 (本番) | Claude + 本人 |
| **Act** | 定着 / 巻き戻し / 次の仮説。結果を `result.md` に書き、次の Plan に渡す | 本人が判断 |

守ること:
- 本番への反映は本人のマージだけ。巻き戻しも本人の判断 (Claude は提案まで)。
- 測った後に規則を変えない。変えるなら新しいカード番号で登録し直す。
- ログに出すのは数・真偽・時間だけ。会話の本文・予定の中身は出さない。
- 本人の評価も指標にする: 使った後に **1〜5 点 + 一言** を伝えてもらい、`field.md` に記録する。

## 2. サイクル 0 — 今の状態を測る (これから約 4 回分の利用)

プロンプトもデザインも変えずに、次の 2 つを同じ利用で集める:
1. **EXP-002 の本番判定**: chat の成功 20 件で、比 `first_chunk_ms / total_ms` を判定する (事前登録済み)
2. **A の改善前の値**: 1 回の会話で予定登録までに何往復かかったか、登録まで届いたか、本人の点数

A の改善前の値を取るため、計測を 2 項目足す (C0 の唯一の変更。プロンプト・画面は変えない):
- `history_len`: そのリクエストまでの会話の往復数 (数だけ)
- `plan_proposed`: 返答に予定案 (```json```) が含まれたか (真偽だけ。中身は見ない)

→ 「会話の始まり (`history_len` = 0) から、最初の `plan_proposed` = true までの往復数」と、「そのあと `calendar/create` が 200 になったか」が出せる。

**プロンプトを変えるのは、EXP-002 の 20 件がそろってから。** 先に変えると返答の長さが変わり、EXP-002 の比が混ざる。

## 3. サイクル A — 質問の中身 (システムプロンプト)

- 今の流れ: 毎回 5 段階を必ず踏む (What と Why → 時間とゴール → プラン → 判定基準 → カレンダー登録)
- [仮説の候補] 往復が多すぎて、登録まで届く前にやめている / 同じことを 2 度聞いている
- 指標:
  - 予定登録までの往復数 (中央値)
  - 登録まで届いた会話の割合
  - 本人の点数
- 変更の候補 (1 サイクル 1 つ):
  - 最初の質問をまとめる
  - 既に分かっていることは聞かない
  - 判定基準の段を任意にする
- 判定規則は C0 の値を見てから、A の `request.md` で事前登録する

## 4. サイクル B — レイアウト

- 対象: チャットと予定欄の配置、スマホ幅での表示、入力欄・ボタンの位置
- 指標:
  - 画面検査のレーン (RUNTIME_STRUCTURAL / INTERACTION / A11Y_AUTOMATED、デスクトップとスマホ幅 375px)
  - 本人の点数
  - A の往復数・到達率 (悪化していないこと)
- 課題: ログイン後の画面は自動検査で開けない。B の Plan で、ログインせずに画面を確認する方法 (開発時だけの確認用の表示など) を決める

## 5. サイクル C — 見た目

- まず方向性を 2〜3 案出して、本人に選んでもらう (`design-directions`)。案ごとに、何を捨てる案かを明記する
- 選んだ案を実装し、次の検査を通す:
  - デザインレビュー (`fable-design-loop`: 視覚・a11y・動きと状態)
  - 画面検査のレーン
- 既知の指摘: タブのタイトルが Next.js の既定のまま「Create Next App」(EXP-002 F1)

## 6. 進め方の目安

| サイクル | 始める条件 | 目安 |
|---|---|---|
| C0 | 計測 2 項目を本番へ (本人のマージ) | 本人の利用 約 4 回 |
| A | EXP-002 の 20 件がそろった | 変更 1 つ → 利用 約 4 回 |
| B | A の判定が出た | 同上 |
| C | B の判定が出た | 方向性の選択 → 変更 → 利用 |

1 サイクルで結論が出なければ (判定不能)、同じテーマでもう 1 周するか、次のテーマへ進むかを本人が決める。
