# ai-planner の目標の木 (KGI → KPI → KDI) と成長の回し方

Date: 2026-09-30 / 上位: `docs/pdca-spec.md` (カードの判定) / 並列の作り方: `docs/parallel-cycle-spec.md`
きっかけ: 本人 (2026-09-30・点数 3)「PDCA のように KGI と KPI を決めて KDI を設定して継続的に回して改善していく。少しずつ成長していく仕様にしたい」

**目標の値は「仮」。本人が決める (Human Gate)。** Claude は値の提案と、実績の集計までを行う。

## 1. 目標の木

```text
KGI  計画をそのまま使える (本人の点数)
 ├─ KPI-1 登録まで届く      ← どの利用でも最後まで行ける
 ├─ KPI-2 往復が少ない      ← 疲れずに計画ができる
 ├─ KPI-3 待たされない      ← 返答が早く出始める
 └─ KPI-4 困りごとが消える  ← 同じ不満が 2 度出ない
KDI  (Claude と本人が毎週やること)
 ├─ KDI-1 使う   KDI-2 伝える   KDI-3 カードを閉じる
 └─ KDI-4 事前登録を守る   KDI-5 振り返る
```

## 2. 定義・今の値・目標 (仮)

「直近 5 回」= `evidence/FIELD-LOG.md` の本番とローカルの利用のうち新しい 5 行 (5 行未満ならある分・件数を併記)。

| 指標 | 定義 (出典) | 今の値 (2026-09-30) | 目標 (仮) |
|---|---|---|---|
| **KGI** 計画の使える度 | 点数のある利用の、直近 5 回の平均点 (FIELD-LOG の点数) | **2.5** (2 件: 2・3) | 4.0 以上 |
| KPI-1 登録まで届く率 | 予定の登録 (`api/calendar/create` 200) まで届いた利用 ÷ 利用 (上限 429 で止まった利用は分母から外し、件数を併記) | 3/3 = 100% (上限で止まった 1 件を除く) | 100% を保つ |
| KPI-2 往復数 | 予定案が出るまでの往復数の中央値 (`history_len` ÷ 2 + 1) | **6** (4・6・13) | 5 以下 |
| KPI-3 待ち | `api/chat` 200 の `first_chunk_ms` の中央値 (直近 5 回の利用の全返答) | 1624 ms (EXP-006 確認の 13 件) | 1500 ms 以下 |
| KPI-4 再発 | 一番困ったことが、定着済みの仮説と同じだった回数 | 0 | 0 を保つ |
| KDI-1 使う | 本人の利用回数 / 週 (FIELD-LOG の行数) | 4 回 (すべて 2026-09-30) | 3 回以上 / 週 |
| KDI-2 伝える | 点数と一番困ったことが、利用後 1 時間以内にそろった割合 | 2/4 | 100% |
| KDI-3 カードを閉じる | 定着・巻き戻し・判定不能のどれかになったカードの数 / 週 | 4 (EXP-001・002・003・005・09-28 の週) | 1 枚以上 / 週 |
| KDI-4 事前登録 | `request.md` が変更より前の commit になっていたカードの割合 (git の順番) | 4/4 (EXP-003〜006・`git merge-base --is-ancestor` で確認。EXP-002 は変更 commit を特定していないので数えていない) | 100% を保つ |
| KDI-5 振り返り | 閉じたカードのうち、`docs/cycle-lessons.md` に 1 行以上残したものの割合 | 対象なし (仕様は今日から) | 100% |

KGI は本人の声、KPI はログの数、KDI は行動の数。**KPI が良くなっても KGI が上がらなければ、KPI の選び方を疑う** (`pdca-spec.md` §4 と同じ考え)。

## 3. カードと KPI をつなぐ

- `request.md` の 1 節目に **「動かしたい KPI」** を 1 つ書く (例: H-08 → KPI-2)
- 次のカードは **目標から一番遠い KPI** を動かす仮説から選ぶ。同じくらい遠ければ、KGI に近い方 (本人の一言に出たもの) を先にする
- カードの判定は今までどおり `request.md` の規則で行う。KPI は「どこを狙うか」を決めるために使い、合否には使わない (指標を後から合否に使うと、測った後で規則を変えることになる)

## 6. 少しずつ成長させる規則 (目標の上げ方)

- **上げる**: ある指標が **2 週続けて目標を満たしたら**、目標を 1 段上げる (例 KGI 4.0 → 4.3、KPI-2 5 → 4、KPI-3 1500 → 1200 ms)。上げるかは月に 1 回、本人が決める
- **戻す**: 上げた後に 2 週続けて下回ったら、前の目標へ戻し、下回った理由を `docs/hypotheses.md` に観察として足す
- **増やさない**: 指標は KGI 1・KPI 4・KDI 5 までにする。新しく足すなら 1 つ外す (測るものが増えると、記録が続かなくなる)
- **数が少ない週**: 利用が 2 回未満の週は KGI・KPI を「判定不能」と書き、目標の上げ下げに数えない
